> **Précédemment.** Le site est construit, vérifié, mis en production et copiable dans une sandbox. Toutes les parties précédentes ont décrit le projet par couches ; celle-ci suit une fonctionnalité de bout en bout.

Une **étude de cas** prend une fonctionnalité et la traverse de part en part : les types, les données, l’état, l’affichage, l’accessibilité, les vérifications, les tests. Celle-ci suit le moteur des **tutoriels interactifs** : un petit module (`apps/web/src/features/tours/`, six cents lignes de moteur, et un fichier par tuto) qui touche presque tout ce que les parties précédentes ont décrit.

Un tutoriel ne se lit pas : il se **fait**. Sur la vraie page, l’écran s’assombrit, seul l’élément de l’étape en cours reste éclairé et actif, une bulle dit quoi faire, et l’on passe à l’étape suivante en faisant l’action demandée — cliquer, taper, changer de page. Le premier tuto du projet guide un administrateur dans la création d’un post — une actualité du mur de l’accueil.

## Un tuto est une donnée 📋

Le moteur ne sait rien des actualités. Il sait lire une **description** de tuto, écrite en données : un objet par tuto, dans son propre fichier. Ajouter un tuto, c’est écrire des données, pas du code. Le type de cette description est le contrat entre les auteurs de tutos et le moteur :

Le tuto **crée** un vrai article, en brouillon : il agit sur les vraies données, et le dit dans ses bulles (« vous pourrez supprimer l’article ensuite »). Un tuto qui publierait quelque chose, ou supprimerait, serait une autre affaire : il ne guiderait pas, il agirait à la place de l’utilisateur.

Une règle les tient tous : **un tuto n’envoie rien que d’autres verraient, et ne fait rien d’irréversible**. Il montre le bouton « Envoyer » d’une demande au club, il ne le clique pas : une demande partie arrive dans la boîte du bureau, avec un accusé de réception, et ne se rattrape plus. Les deux seuls tutos qui créent quelque chose — un post, un flash info du ruban — créent un brouillon que personne d’autre ne voit, et le disent.

Le public de « Traiter une demande » est `member`, pas `admin` : un membre d’un groupe responsable d’une catégorie (le support du site) traite les demandes sans être administrateur. Le public décide de qui se voit proposer le tuto ; c’est la page qui, elle, n’affiche la boîte qu’à ceux qui traitent une catégorie.

<Callout type="info">
Deux mots se croisaient dans le projet : le code et cette documentation appellent « actualité » un **post** (`Post`, le mur « Actualités du club »), et le tableau de bord appelait aussi « Actualités » les **messages du ruban** (`BreakingNews`) — le panneau public s’intitulait même « Actualités du club », comme le mur. Écrire les tutos, qui citent l’interface mot pour mot, l’a rendu visible. Les messages du ruban s’appellent désormais **flash info**, partout où l’utilisateur les voit ; le tuto pilote, « Créer un post ».
</Callout>

Le public d’un tuto décide de **ce qui est proposé**, pas de ce qui est permis. Un membre qui forcerait le lancement d’un tuto d’administration arriverait sur des pages du tableau de bord, que le proxy et les procédures lui refusent (partie « Authentification et droits ») : le tuto n’ouvre aucun droit.

Une classe CSS change avec le style, un texte avec la langue ou une reformulation, une position avec la mise en page : un tuto qui s’y accrocherait casserait à chaque retouche. `data-tour` ne sert qu’aux tutos ; il ne change rien à l’affichage, et dit à qui modifie le composant que **quelqu’un dépend de ce nom** (partie « Démarrer », chapitre « Façon de travailler »).

Les noms suivent la page et le rôle de l’élément (`posts.list.create`, `posts.form.title`) : on devine, en lisant le tuto, où se trouve chaque cible.

## Une garde pour le contrat

Un contrat que rien ne vérifie finit rompu. Renommer l’attribut, déplacer le bouton dans un autre composant, retirer un tuto du registre : le code compile, le lint ne dit rien, et le tuto se bloque chez l’utilisateur — ou n’apparaît plus. `scripts/check-tour-targets.mjs`, lancé par `pnpm check` (partie « Qualité », chapitre « Les gardes maison »), cherche trois ruptures :

## À suivre

Un tuto est une liste d’étapes. Le moteur doit la dérouler : se souvenir de l’étape en cours à travers plusieurs pages, trouver l’élément visé, assombrir le reste, et reconnaître l’action attendue.
