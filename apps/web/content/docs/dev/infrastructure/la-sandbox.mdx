> **Précédemment.** La production suit un ordre précis — le code, la migration, le nouveau conteneur — et le site garantit lui-même, en démarrant, les données dont il a besoin.

Le projet est aussi une vitrine : quelqu’un qui veut l’essayer ne doit avoir besoin ni d’un compte Cloudflare, ni d’une base Postgres, ni d’un serveur SMTP, ni des données des membres. La **sandbox** est un fichier compose qui monte tout cela sur sa machine, avec Docker :

```bash
git clone … && cd akfc
docker compose -f docker-compose.sandbox.yml up -d --build
```

Le site répond alors sur `http://localhost:3010`, les fichiers stockés sur `http://localhost:9001`, et les e-mails envoyés par le site s’affichent sur `http://localhost:8025`. Rien ne sort de la machine.

## Une adresse pour le serveur, une autre pour le navigateur

Le site envoie les fichiers au stockage par des **URL signées** : le navigateur les reçoit et y dépose le fichier directement (partie « Stockage et médias »). Dans la sandbox, le site parle au stockage sous le nom `storage:8333`, qui n’existe que dans le réseau Docker ; le navigateur, lui, l’atteint par `localhost:9000`, le port publié. En production, `R2_PUBLIC_ENDPOINT` est absente : serveur et navigateur atteignent R2 à la même adresse publique. La signature couvre l’adresse : une URL signée pour `storage:8333` puis réécrite en `localhost:9000` serait refusée. Il faut signer directement pour l’adresse que le navigateur utilisera.

Le seed est **idempotent** : relancé à chaque `up`, il complète sans dupliquer. Ce que l’essai a créé (des membres, des pages, des fichiers) reste d’un redémarrage à l’autre, dans les volumes.

## Tout effacer

<DocsTable columnsJson='["Commande", "Ce qu’elle fait"]' rowsJson='[["docker compose -f docker-compose.sandbox.yml up -d --build", "Construit et démarre tout ; relancée, reprend l’essai là où il était."], ["docker compose -f docker-compose.sandbox.yml stop", "Arrête les conteneurs, garde les données."], ["docker compose -f docker-compose.sandbox.yml down -v", "Supprime les conteneurs ET les volumes : base et fichiers repartent de zéro au prochain up."]]' />

`-v` est ce qui distingue « arrêter » de « effacer » : sans lui, les volumes nommés (`sandbox_pgdata`, `sandbox_storage`) restent, avec tout ce qu’ils contiennent.

<Callout type="info">
La sandbox, l’environnement de développement (`docker-compose.dev.yml`, partie « Démarrer ») et les tests de bout en bout (partie « Qualité ») ont chacun leurs ports, leur base et leur stockage : ils peuvent tourner ensemble sur la même machine sans se marcher dessus.
</Callout>
